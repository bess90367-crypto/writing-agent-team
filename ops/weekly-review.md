# Weekly Review Protocol

A scheduled review should audit the repository and recent project conversations.

## Review checklist

1. New durable preferences not yet captured.
2. Repeated user corrections that deserve a regression case.
3. Contradictory rules.
4. Duplicate rules that can be merged.
5. Over-broad rules created from a one-off situation.
6. Routing errors.
7. Examples that no longer match current preferences.
8. New recurring work domains.
9. Attachment-derived learning that should be distilled.
10. CHANGELOG and VERSION consistency.

## Change discipline

- Prefer small targeted changes.
- Do not rewrite every prompt during routine maintenance.
- Preserve backward-compatible behavior unless the user's preference clearly changed.
- If there is no meaningful improvement, make no change.
